# 시큐에이드 (SecuAid) — 기획서 요약 (1~2p 제출용)

> Liner .EXE-THON 2026 · 개인 참가 김형철(Eden) · 구현 v0.9 (2026-11-20)
> 시큐에이드(SecuAid = Security + Aid) — 보안사고 첫 72시간 응급처치 에이전트. 전체 기획서 `docs/시큐에이드_기획서_v1.1.pdf`의 요약본입니다.

## 1. 문제 — 메일 계정이 뚫린 날, 작은 회사에는 담당자가 없다

전담 보안 인력이 없는 1~50명 규모 회사의 IT 담당자·대표·재무 담당자는 업무 메일 계정이 탈취(BEC)된 첫 몇 시간 동안 무엇부터 해야 할지 모릅니다. 현장에서 반복되는 실수는 다섯 가지입니다.

1. **돈과 계정을 늦게 막는다** — 사칭 메일을 받고도 "일단 원인을 알아보고" 은행 연락을 미룹니다. 계좌 변경 요청은 단 한 번의 이체로 끝납니다.
2. **암호만 바꾸고 해결됐다고 본다** — 세션·토큰·앱 비밀번호·OAuth 동의·전달 규칙이 그대로 남습니다.
3. **당황해서 증거를 지운다** — 의심 규칙을 삭제하거나 PC를 포맷해 유출 범위 입증이 사라집니다.
4. **신고 대상·기한을 모른다** — 침해사고 신고(24시간)와 개인정보 유출 통지(72시간)의 기산점과 요건을 놓칩니다.
5. **침해된 계정으로 사과 메일을 보낸다** — 공격자가 그 메일을 보고, 수신자는 진위를 구분할 수 없습니다.

기존 자료는 "읽는 문서"입니다. 가이드와 체크리스트는 있지만, 사고 당일 당황한 사람은 수십 쪽을 읽고 자기 상황에 맞는 줄을 찾지 못합니다.

## 2. 해결 — 노하우를 대화로 따라 할 수 있는 에이전트로

**"신입이 반복하는 실수"를 "누구나 피하는 실수"로.** 20년 현장 경험을 55쪽 플레이북으로 정리해 두었고, 이 에이전트는 그 플레이북을 사고 당일에 실제로 쓰이게 만드는 수단입니다.

사용 흐름(데모 시나리오 기준):

| 단계 | 사용자 | 에이전트 |
|---|---|---|
| ① 인지 | "거래처에서 우리가 계좌를 바꿨냐고 전화가 왔어요" | 인지 시각 기록, 판별 질문 시작 |
| ② 판별 | 의심 메일 원본(헤더 포함) 붙여넣기 | 계정 침해 / 스푸핑 / 유사 도메인 판정 + 근거 |
| ③ 통제 | 엔타라 로그인·감사 로그 붙여넣기 | 의심 IP·숨김 규칙·지속성 수단 탐지, 지금 할 일·하지 말 것 제시 |
| ④ 판단 | "이미 1,870만 원을 송금했대요" | 심각도 P1 격상, 은행 우선 행동, 신고·통지 대상과 마감 계산 |
| ⑤ 문서 | "신고해야 하나요?" | 근거 있는 판단 + 통지문·신고서 초안 10종 |

**지키는 원칙**

- **확인 / 추정 / 미확인을 섞지 않는다** — 모든 문장이 근거 수준을 표시합니다. "결과 없음"을 "피해 없음"으로 바꿔 쓰지 않습니다.
- **모르는 건 모른다고 한다** — 서버 자체 장악(root 탈취)은 플레이북 범위 밖이므로 아는 척하지 않고 초동 조치 후 전문 대응 조직 호출을 권고합니다.
- **민감정보를 밖으로 보내지 않는다** — 모델로 보내기 전 주민번호·연락처·계좌·이메일을 마스킹합니다.
- **제출은 사람이 한다** — 초안과 발송 전 통과표까지만 만들고, 최종 판단·발송은 담당자가 합니다.

## 3. Liner API 활용 — 왜 Liner여야 하는가

| 역할 | API | 왜 필요한가 |
|---|---|---|
| 대화·판단 해석·문장 | Router API `liner-mark-1.3` (`/chat/completions`) | 사용자의 구어("계좌 바꿨냐고 전화가 왔어요")를 구조화된 사실로 바꾸고, 사건 브리핑과 문서 문장을 씁니다. 사건 전체를 지휘하는 두뇌입니다. |
| 법령·공지 최신성 | **Search Agent API** (`/agents/search`) | 신고 기한(정보통신망법 §48조의3 24시간, 개인정보보호법 §34조 72시간)을 **출처 링크와 함께** 재확인합니다. 코드 규칙과 답변이 다르면 경고(drift)를 띄웁니다. 법은 바뀌고, 학습 시점 지식으로 신고 기한을 안내하는 것은 도메인에서 받아들일 수 없습니다. |
| 공식 창구·참고 자료 | Search API (`/tools/search/web`) | KISA 보호나라(118)·개인정보포털 등 실제 신고 창구를 함께 제시합니다. Search Agent와 동시에 호출합니다. |
| 유형별 즉답 | Quick Answer Agent API (`/agents/quick-answer`) | 10대 사고 유형을 고르면 "지금 10분 안에 할 일"을 출처와 함께 짧게 답합니다. |
| 사건 차트 | Visualization API (`/tools/visualization`) | 이 사건의 0~72시간 대응을 한 장의 차트로 그립니다(화면 데이터에 접근하지 못하는 격리된 창에서 실행). |

**속도 설계** — 판정·할 일·기한은 규칙 엔진이 즉시 돌려주고, Liner 문장과 근거는 뒤따라 병렬로 붙습니다. 사용자는 Liner를 기다리지 않고, Liner가 늦거나 실패해도 판정은 그대로 유효합니다.

**설계의 핵심: 계산은 규칙, 판단과 문장은 모델.** 심각도·기한·타임라인·신고 대상 판단은 결정적 규칙 엔진(같은 입력 → 같은 출력)이 만들고, LLM은 해석과 문장만 맡습니다. "AI가 기한을 틀리면?"이라는 질문에 대한 구조적 답입니다. Liner가 응답하지 못하면 규칙 기반으로 자동 전환되어 데모와 실사용이 멈추지 않습니다.

## 4. 확장성과 임팩트

- **누가 쓰는가** — 보안 인력 없는 중소기업(사고 당일 직접 대응), IT 아웃소싱(MSP)·보안관제 업체(고객사 사고를 같은 기준으로 초동 처리), 사이버 보험·법무 자문(사고 접수 시 표준화된 확인/미확인 정리), 교육(가상 시나리오로 "첫 10분" 훈련).
- **어떻게 넓히는가** — 플레이북만 바꾸면 다른 사고(랜섬웨어·정보 유출·내부자)에 적용됩니다. 엔진은 "결정 트리 + 신고 규칙 + 템플릿" 데이터를 읽는 구조라, 웹사이트 침해 대응 플레이북은 같은 형식으로 추가할 수 있습니다. 로그 파서를 추가하면 Google Workspace·국내 호스팅 메일로 확장됩니다.
- **목표 지표** — 첫 경영진 보고까지 걸리는 시간(플레이북만 볼 때 대비 단축), "하지 말 것" 위반 0건, 신고 기한 계산 오차 0건(결정적 엔진), 모든 사실 문장의 확인/추정/미확인 표시율 100%.
- **한계를 먼저 밝힌다** — 법률 자문이 아니며, 자동 신고·자동 발송은 하지 않습니다. 판단의 근거와 모르는 것을 함께 보여 주는 것이 이 제품의 신뢰 기반입니다.
