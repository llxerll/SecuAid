시큐에이드 SecuAid = Security + Aid

보안 담당자가 없는 회사의 첫 72시간을 지키는 보안사고 응급처치 에이전트
Liner .EXE-THON 2026 · 개인 참가 김형철(Eden) · 구현 v0.14 (2026-11-22) · 서비스 https://secuaid.vercel.app · 소스 https://github.com/llxerll/SecuAid
한 줄 요약 — 보안 담당자가 없는 작은 회사의 경리·실무자가 사고 당일 평소 말투로 상황을 적으면, 지금 할 일 하나와 법정 신고 기한, 증거 확보 방법, 신고서·통지문 초안까지 첫 72시간을 순서대로 받는 보안사고 응급처치 에이전트.

1. 고객과 문제 — 담당자도, 로그도 없이 72시간이 흘러갑니다

고객 전담 보안 인력이 없는 1~50명 규모 회사의 경리·실무자·대표. 사고는 "보안팀"이 아니라 이들 앞으로 먼저 옵니다.
예) 직원 12명 물류회사 경리 담당자에게 거래처 전화가 옵니다 — "계좌 바꾸셨다면서요? 오늘 아침에 1,870만 원 보냈는데요."
문제무엇이 어려운가
1보안 담당자 없이 — 경리·실무자가 혼자 대응 당황하면 "원인부터 알아보자"며 은행 연락을 미루고, 암호만 바꾸고 끝내거나 의심 메일·파일을 지워 증거를 잃습니다.
2법정 신고 24·72시간, 은행 지급정지 골든타임 침해사고 신고 24시간(정보통신망법), 개인정보 유출 신고·통지 72시간(개인정보 보호법) — 모두 "알게 된 때부터" 흐릅니다. 송금 사기는 이체 직후 몇 시간이 회수를 가르는데, 무엇을 언제까지 해야 하는지 알려 주는 사람이 없습니다.
3'로그'가 뭔지도 모른 채 증거 확보·신고서 작성 어디서 무엇을 남기고 신고서를 어떻게 써야 하는지 막막합니다. 가이드는 있지만 수십 쪽의 "읽는 문서"라, 사고 당일 자기 상황에 맞는 줄을 찾지 못합니다.

2. 해결책 — 그 첫 72시간을 시큐에이드가 정리합니다

해결시큐에이드가 하는 일푸는 문제
1일상어로 상황만 적으면 규칙 엔진이 유형·심각도(P1~P4)·72시간 시계·'지금 가장 먼저' 할 일 1개를 즉시 제시. 필요한 것만 버튼으로 묻고(모르면 〔미확인〕), 할 일마다 [어떻게?]에 은행 지급정지 전화 대본·준비물.① 혼자 대응
② 골든타임
2로그가 없어도 증거부터 증거 확보 도우미가 쓰는 메일·PC·NAS·쇼핑몰별로 무엇을 어디서 남길지 안내, 못 구하면 업체에 보낼 로그 보존 요청 메일, Liner Search로 업체 공식 안내 · 기억나는 일은 진술 타임라인으로.③ 증거
3체크한 일만 담아 문서까지 신고 대상을 해당·검토·판단 보류로 판정하고 KISA·개인정보보호위원회 신고서, 정보주체 통지문, 고객·은행·직원 안내, 경영진 보고 초안(DOCX)을 사건에 맞게 생성 — 체크한 일과 시각만 반영.② 법정 기한
③ 신고서
① 말하기"거래처에서 계좌 바꿨냐고 전화 왔어요"
② 즉시 판정유형·심각도·기한·할 일
③ 버튼 답변필요한 것만 · 모르면 미확인
④ 하나씩 실행지금 가장 먼저 → [했어요]
⑤ 보고·신고카톡 요약 · 마감 알림 · 문서

3. 왜 믿고 쓸 수 있나 — 차별점과 원칙

  • 판단은 규칙 엔진, 말과 근거는 Liner, 결정은 사람 — 기한·심각도는 결정적 코드(같은 입력 → 같은 결과)로 고정하고, Liner는 쉬운 설명·출처·법령 재확인을 맡습니다. Liner가 늦거나 실패해도 판정·기한·문서는 그대로 동작합니다.
  • 하지 않은 조치를 했다고 쓰지 않음 · 확인/추정/미확인을 섞지 않음 · 모르는 범위(서버 장악 등)는 아는 척하지 않고 전문가 호출.
  • 실무 기준 — 참가자의 보안 실무 경험을 바탕으로 AI와 함께 정리한 55쪽 초동대응 플레이북의 판단 기준을 코드로 옮기고 10대 사고 유형으로 넓혔습니다. 개인정보는 가린 뒤에만 외부(Liner)로 보냅니다.

데모 데이터는 모두 가상입니다(.example 도메인, RFC 5737 IP, 가상 회사·은행·계좌). 시나리오 4종: 계정 탈취→계좌 변경 사칭(송금 후 P1) · 유사 도메인 사칭(신고 비해당) · 서버 root 탈취(범위 밖) · 랜섬웨어(몸값 지불 금지).

4. Liner API 활용 방식 — 5종

판단은 규칙 엔진이, 말과 근거는 Liner가, 결정과 제출은 사람이. 기한처럼 틀리면 안 되는 계산은 결정적 코드(같은 입력 → 같은 결과)로 고정하고, Liner는 그 결과를 사람이 이해하고 확인하게 만듭니다. 판정은 즉시 나오고 Liner는 뒤따라 병렬로 붙으며, Liner가 늦거나 실패해도 판정·기한·문서는 그대로 동작합니다.

5. 다른 조직·직무로의 확장 가능성

다른 조직

  • IT 유지보수(MSP)·보안관제 업체 — 고객사 사고를 같은 기준으로 초동 처리하고 보고서를 표준화
  • 사이버보험사·법무 자문 — 사고 접수 시 확인/추정/미확인이 나뉜 경위서와 조치 기록을 바로 받음
  • 세무·회계 사무소, 프랜차이즈 본사 — 거래처·가맹점의 계좌 변경 사칭과 랜섬웨어 1차 안내
  • 교육·훈련 — 가상 시나리오로 "첫 10분" 모의 훈련

다른 직무·사고 유형

  • 재무·경리 — 송금 사기 대응(지급정지 전화 대본, 은행 요청서)
  • 개인정보 보호 담당 — 유출 신고·정보주체 통지 기한과 문안
  • 대표·경영진 — 5줄 보고와 결정 사항
  • 사고 유형 추가 — 엔진은 "판단 구조·신고 규칙·문서 양식" 데이터를 읽는 구조라, 데이터만 더해 넓힙니다. 지금 10대 유형 중 5종 심화, 5종 공통 흐름 지원
상용화 설계 — 지금은 해커톤 제출용(서버 DB·로그인 없음, 사건은 사용자 브라우저에 보관)입니다. 상용에서는 국내(서울) 리전 + 작업 큐 · 회사별 DB와 암호화·감사 로그 · 회사 계정과 2단계 인증(담당자·대표·외부 전문가 역할) · M365·Google Workspace 로그 자동 수집 · 마감 전 알림톡·문자 · 규칙 버전 관리와 정기 법령 재확인으로 바꿉니다. 단계: ① 시범 운영(계정·저장·알림, 시범 고객 10곳) → ② 로그 자동 수집·평시 점검 → ③ 보험사·MSP 연계와 ISMS-P 준비.

6. 기대 효과와 검증

비교 항목기존 (가이드 문서만 있을 때)시큐에이드 도입 후
초동 판단·우선순위수십 쪽 문서를 뒤져 내 상황에 맞는 줄을 직접 찾음구어 입력 즉시 심각도(P1~P4)와 '지금 가장 먼저' 1개 제시
법정 기한·신고서기산점·요건 혼동, 백지에서 신고서·통지문 작성결정적 엔진이 24h·72h 시계 계산 + 체크한 일만 반영한 초안 6~10종(DOCX) 생성
증거·로그 부재 시무엇을 보존할지 몰라 삭제·포맷 등 2차 실수환경별 증거 확보 도우미 + 업체 요청 메일 + 진술 타임라인 구축
  • 목표 지표 — 첫 경영진 보고까지 걸리는 시간 단축 · "하지 말 것" 위반 0건 · 신고 기한 계산 오차 0건(결정적 엔진) · 모든 사실 문장의 확인/추정/미확인 표시율 100%.
  • 한계와 책임 — 법률 자문이 아니며 자동 신고·자동 발송은 하지 않습니다. 판단 근거와 모르는 것을 함께 보여 주는 것이 이 제품의 신뢰 기반입니다.
