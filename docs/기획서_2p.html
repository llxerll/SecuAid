시큐에이드 SecuAid = Security + Aid

보안 담당자가 없는 회사의 첫 72시간을 지키는 보안사고 응급처치 에이전트
Liner .EXE-THON 2026 · 개인 참가 김형철(Eden) · 구현 v0.14 (2026-11-21) · 서비스 https://secuaid.vercel.app · 소스 https://github.com/llxerll/SecuAid

1. 누가, 어떤 문제로, 얼마나 불편한가

누가 — 전담 보안 인력이 없는 1~50명 규모 회사의 대표·경리·IT 겸임 담당자. 메일 계정 탈취·거래처 계좌 변경 사칭(BEC)·랜섬웨어가 터진 날, 처음으로 "보안사고 담당자"가 됩니다.

어떤 문제 — 현장에서 반복되는 실수는 정해져 있습니다.

  1. 돈과 계정을 늦게 막는다 — "원인부터 알아보자"며 은행 지급정지 요청을 미룹니다. 송금 사기는 이체 직후 몇 시간이 회수를 가릅니다.
  2. 암호만 바꾸고 끝낸다 — 세션·앱 비밀번호·전달 규칙이 남아 공격자가 계속 머뭅니다.
  3. 당황해서 증거를 지운다 — 의심 규칙 삭제·PC 포맷으로 유출 범위를 입증할 수 없게 됩니다.
  4. 신고 대상과 기한을 모른다 — 기한은 주체와 유형에 따라 다릅니다. 정보통신서비스 제공자의 침해사고 신고는 24시간(정보통신망법), 개인정보 유출 통지는 72시간, 유출 신고는 1천 명 이상·민감/고유식별정보·외부 불법 접근 등 해당 시 72시간(개인정보 보호법). 기한은 "처음 안 시각"부터 흐릅니다.
  5. 로그가 뭔지 모른다 — 증거를 어디서 어떻게 확보하는지, 업체에 무엇을 요청해야 하는지 모릅니다.

얼마나 불편한가 — 가이드와 체크리스트는 이미 있지만 수십 쪽의 "읽는 문서"입니다. 사고 당일 당황한 사람은 자기 상황에 맞는 줄을 찾지 못하고, 기한이 흐르는 동안 무엇부터 할지 정하지 못합니다. 신고서·통지문도 백지에서 씁니다.

2. 에이전트의 해결 방식

① 평소 말투로 말하기"거래처에서 계좌 바꿨냐고 전화 왔어요" · 로그·메일 원본은 있으면 첨부
② 즉시 판정규칙 엔진이 유형·심각도(P1~P4)·법정 기한·할 일을 바로 계산
③ 버튼으로 답하기신고 판단에 필요한 것만 질문 · 모르면 '모르겠어요'(〔미확인〕)
④ 위에서부터 하나씩'지금 가장 먼저' + [어떻게 하나요?](연락처·준비물·순서·전화 대본)
⑤ 기한·문서72시간 시계 · 신고서·통지문·경영진 보고 초안(DOCX)
  • 로그가 없어도 — 증거 확보 도우미(M365·Google·국내 메일·PC·NAS·쇼핑몰별로 무엇을 어디서 확보할지, 업체에 보낼 로그 보존 요청 메일), 기억나는 일을 시각과 함께 쌓는 진술 타임라인.
  • 실제로 쓰는 날을 위해 — 창을 닫아도 이어 하기, 다른 PC로 사건 파일 옮기기, 사장님께 보낼 카카오톡 요약, 신고 마감 달력 알림.
  • 원칙 — 확인/추정/미확인을 섞지 않음 · 하지 않은 조치를 했다고 쓰지 않음(신고서의 '현재까지의 대응'은 체크한 일과 시각으로만) · 모르는 것은 모른다고 하고 전문가 호출 · 개인정보는 가린 뒤에만 외부로 · 제출과 발송은 사람이.

데모 데이터는 모두 가상입니다(.example 도메인, RFC 5737 IP, 가상 회사·은행·계좌). 시나리오 4종: 계정 탈취→계좌 변경 사칭(송금 후 P1 격상) · 유사 도메인 사칭(신고 비해당 판별) · 서버 root 탈취(범위 밖 — 아는 척하지 않음) · 랜섬웨어(몸값 지불 금지).

3. Liner API 활용 방식 — 5종

판단은 규칙 엔진이, 말과 근거는 Liner가, 결정과 제출은 사람이. 기한처럼 틀리면 안 되는 계산은 결정적 코드(같은 입력 → 같은 결과)로 고정하고, Liner는 그 결과를 사람이 이해하고 확인하게 만듭니다. 판정은 즉시 나오고 Liner는 뒤따라 병렬로 붙으며, Liner가 늦거나 실패해도 판정·기한·문서는 그대로 동작합니다.

4. 다른 조직·직무로의 확장 가능성

다른 조직

  • IT 유지보수(MSP)·보안관제 업체 — 고객사 사고를 같은 기준으로 초동 처리하고 보고서를 표준화
  • 사이버보험사·법무 자문 — 사고 접수 시 확인/추정/미확인이 나뉜 경위서와 조치 기록을 바로 받음
  • 세무·회계 사무소, 프랜차이즈 본사 — 거래처·가맹점의 계좌 변경 사칭과 랜섬웨어 1차 안내
  • 교육·훈련 — 가상 시나리오로 "첫 10분" 모의 훈련

다른 직무·사고 유형

  • 재무·경리 — 송금 사기 대응(지급정지 전화 대본, 은행 요청서)
  • 개인정보 보호 담당 — 유출 신고·정보주체 통지 기한과 문안
  • 대표·경영진 — 5줄 보고와 결정 사항
  • 사고 유형 추가 — 엔진은 "판단 구조·신고 규칙·문서 양식" 데이터를 읽는 구조라, 데이터만 더해 넓힙니다. 지금 10대 유형 중 5종 심화, 5종 공통 흐름 지원
상용화 설계 — 지금은 해커톤 제출용(서버 DB·로그인 없음, 사건은 사용자 브라우저에 보관)입니다. 상용에서는 국내(서울) 리전 + 작업 큐 · 회사별 DB와 암호화·감사 로그 · 회사 계정과 2단계 인증(담당자·대표·외부 전문가 역할) · M365·Google Workspace 로그 자동 수집 · 마감 전 알림톡·문자 · 규칙 버전 관리와 정기 법령 재확인으로 바꿉니다. 단계: ① 시범 운영(계정·저장·알림, 시범 고객 10곳) → ② 로그 자동 수집·평시 점검 → ③ 보험사·MSP 연계와 ISMS-P 준비.

6. 목표와 한계

  • 목표 지표 — 첫 경영진 보고까지 걸리는 시간 단축 · "하지 말 것" 위반 0건 · 신고 기한 계산 오차 0건(결정적 엔진) · 모든 사실 문장의 확인/추정/미확인 표시 100%.
  • 한계 — 법률 자문이 아니며 자동 신고·자동 발송은 하지 않습니다. 판단 근거와 모르는 것을 함께 보여 주는 것이 이 제품의 신뢰 기반입니다.
