# 시나리오 1 (메인 데모): 영업관리 계정 탈취 → 거래처 계좌 변경 사칭

> 모든 데이터는 가상입니다. 회사·인물·도메인·계좌는 실재하지 않습니다.
> IP는 문서용 예약 대역(RFC 5737)만, 도메인은 `.example`만 씁니다.

## 플레이북 연결
- 카드: **12.3 침해 계정 피싱 발송** + **12.2 계좌 변경 요청** (겹치면 상위 심각도 기준 → P1~P2)
- 판단: 3.1 신호표, 3.3 계정 침해 vs 스푸핑 vs 유사 도메인
- 함정 장치: 로그는 UTC, 은행·사내 기록은 KST (5.3 시간대 원칙 시연)

## 가상 조직
- (주)한빛물류 `hanbit-logis.example` — 직원 38명, Microsoft 365 사용
- 침해 계정: 영업관리 박서연 `sy.park@hanbit-logis.example`
- 거래처: (주)대성포장 `daesung-pack.example`, 그린로지스 `greenlogis.example`, 미래상사 `mirae-trade.example`

## 기대 결과 (에이전트 평가용)
- 판별: **계정 침해(ATO)** — 보낸편지함·메시지 추적에 발송 기록, SPF/DKIM 통과, 도메인 철자 정확
- 심각도: 처음 P2(계좌 변경 요청·외부 발송) → **송금 사실 확인 시 P1로 격상**
- 0~10분: 미래상사에 은행 지급정지 연락 권고(송금 은행은 거래처 측임에 유의), 계정 일시 중지·세션 철회, 별도 채널
- 금지 경고: 박서연 계정으로 "방금 메일 무시하세요" 발송 금지, 규칙 기록 없이 삭제 금지
- 지속성: 받은편지함 규칙 1건, 앱 비밀번호 1건 발견
- 시간대: 로그인 로그 UTC 01:14 = KST 10:14로 변환해 타임라인 정리
- 신고 판단
  - 침해사고 신고: 정보통신서비스 제공자(홈페이지·고객 문의 운영) → 대상, 마감 **11/20(금) 09:05**
  - 개인정보: 공격자 사서함 열람 확인(`MailItemsAccessed`) + 외부 불법접근 → 유출 신고 검토 대상, **11/22(일) 09:05**. 1천 명 이상 기준도 해당
  - 정보주체 통지(가능성 포함): 검토 대상, **11/22(일) 09:05**
- 문서: 거래처 경고문(T1), 거래 건 확인 요청(T2), 직원 공지(T3), 경영진 5줄(T6), 침해 최초신고서·유출 신고서·통지문 초안

## 데모 입력 순서
1. "거래처 대성포장에서 우리가 계좌 바꿨냐고 전화가 왔어요. 우린 바꾼 적 없어요." → 인지 시각 기록, 판별 질문 시작
2. 의심 메일 원본 `account_change_sent.eml` 붙여넣기 → 헤더 판독: 계정 침해 쪽
3. `entra_signin_log.csv`, `audit_log.csv` 붙여넣기 → 해외 로그인, 숨김 규칙 탐지
4. "방금 미래상사가 오늘 아침에 이미 송금했대요" → P1 격상, 은행 연락 최우선
5. "사서함에 고객 배송 문의가 1,300명분 정도 있어요" → 신고·통지 판단, 문서 생성
