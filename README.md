# 시큐에이드 (SecuAid)

> 중소·소호 기업 보안사고 초동대응 파트너 — 보안 담당자가 없는 회사의 첫 72시간을 지키는 AI
> Liner .EXE-THON 2026 제출작 · **v0.14** · 서비스: https://secuaid.vercel.app/ · 저장소: https://github.com/llxerll/SecuAid

메일 계정이 뚫리거나 파일 서버가 랜섬웨어로 잠긴 날, 보안 담당자가 없는 작은 회사는 무엇부터 해야 할지 모릅니다.
시큐에이드는 담당자가 **평소 말투로 상황을 말하면**(로그·메일 원본이 있으면 붙여넣고, 없어도 됩니다)

1. 사고 유형과 심각도(P1~P4)를 판정하고
2. **지금 가장 먼저 할 일** 하나와, 그 일을 **어떻게 하는지**(연락처·준비물·순서·전화 대본)를 주고
3. 법정 신고·통지 기한을 계산해 **72시간 시계**로 보여 주고
4. 신고서·통지문·경영진 보고 초안(MD·DOCX)을 만들어 줍니다.

**판단은 규칙 엔진이, 말과 근거는 Liner가, 최종 결정과 제출은 사람이 합니다.**

| **문서** | **사건에 해당하는 것만** 만듭니다(아래 목록에서 7~10종): 침해사고 최초신고서 · 개인정보 유출 신고서·정보주체 통지문(유출 판정이 '해당·검토'일 때) · 고객·거래처·직원 안내 · 은행 요청(송금 확인 시) · 보험사 통지(보험 가입 시) · 경영진 보고 · 타임라인 · 랜섬웨어 경과 보고(랜섬웨어일 때). 만들지 않은 문서는 [문서] 탭에 이유를 표시 — 미리보기·복사·MD·DOCX·ZIP |

| **안내** | [사용법] — 그림으로 보는 4단계·화면 구성·자주 묻는 것 · **[Liner 연동]** — Liner API 5종을 어디서 어떻게 쓰는지 · **[해커톤 버전과 상용화 설계]** |

## 2. Liner API 활용 (5종)

화면 오른쪽 위 **[Liner 연동]**을 누르면 같은 내용이 앱 안에서도 나옵니다.

| API | 엔드포인트 · 인증 | 화면에서 | 하는 일 | 코드 |
|---|---|---|---|---|
| **Liner Mark** (`liner-mark-1.3`) | `POST /api/v1/chat/completions` · Bearer | 대화의 'Liner Mark 브리핑' | 규칙 엔진 결과를 쉬운 말로 브리핑 · 구어체에서 유형·시각·있었던 일을 **추정**으로 보탬(규칙 결과를 덮지 않음) | `liner.py: chat()/chat_json()` · `agent.py: _narrate()/_llm_facts()` |
| **Quick Answer** | `POST /api/v1/agents/quick-answer` · x-api-key | 유형별 즉답 가이드 · 대화 속 답변 · 할 일 [어떻게?] | 유형별 첫 대응, 담당자 질문("돈 주는 게 낫지 않나요?")에 사건 맥락으로 답, 내장 안내가 없는 할 일의 방법 — 모두 출처 포함 | `quick_answer()` · `quick_guide()/answer_question()/howto_from_liner()` |
| **Search Agent** | `POST /api/v1/agents/search` · x-api-key | 기한 카드 'Liner 근거 재확인' 배지 | 정보통신망법 §48조의3 · 개인정보 보호법 §34조를 다시 읽고 코드의 기한 규칙과 **차이(drift)**를 표시 | `search_agent()` · `fetch_law_check()` |
| **Search** | `POST /api/v1/tools/search/web` · x-api-key | [증거 확보] [공식 안내 찾기] · 근거 출처 | 업체(가비아·하이웍스·M365 등)의 로그 확인 공식 문서 찾기 · 법령·신고 창구 출처(Search Agent와 동시 호출) | `search_web()` · `app.py: /evidence/search` |
| **Visualization** | `POST /api/v1/tools/visualization` · x-api-key | 72시간 차트 창 [Liner AI 시각화] | 이 사건의 0~72시간 대응을 차트 HTML로 — `sandbox="allow-scripts"` 격리 창에서 표시 | `visualize()` · `agent.py: visualize()` |

**언제 호출되나:** 판정은 규칙 엔진이 즉시 응답하고(`/message`, Liner 대기 없음), Liner는 뒤따라 붙습니다.

- `/enrich`: 사실 해석 → 브리핑 ∥ 가이드 ∥ 답변
- `/law`: Search Agent ∥ Search. 로그로 침해가 확인되거나 "신고해야 하나요?"라고 물을 때 1회 호출합니다.
- Visualization: 버튼을 누를 때만 호출합니다.

**안전장치:**

- **마스킹:** `mask.py`가 주민번호·카드·전화·계좌·이메일·IP를 토큰으로 가린 뒤 Liner로 보내고, 응답에서 복원합니다.
- **시간 제한:** API별로 둡니다(Mark 25초 · Search 15초 · Quick Answer 30초 · Search Agent 50초 · Visualization 55초). 서버리스 60초 한도 안에서 끝납니다.
- **실패해도 동작:** Liner가 실패하거나 키가 없으면 규칙 기반 안내로 대체합니다. 판정·기한·문서는 그대로 동작합니다.

실측(2026-11-21, iad1): Mark 1.6~2.8초, Quick Answer 2.2~3.6초, Search 1.1~1.7초, Search Agent 약 24초.

## 3. 실행

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt          # flask, python-docx

cp .env.example .env                     # LINER_API_KEY=... 입력 (https://platform.liner.com 에서 발급, 코드에 넣지 않음)
python app.py                            # → http://127.0.0.1:8000
```

키가 없으면 **규칙 기반 모드**로 자동 전환됩니다. 판정·기한·할 일·문서는 그대로 나오고, Liner가 맡는 브리핑·답변·근거·AI 차트만 꺼집니다.

CLI:

```bash
python run_demo.py                                  # S1 메인 시나리오
python run_demo.py --scenario s4_ransomware         # 랜섬웨어
python run_demo.py --category CAT07_WEB_DB_LEAK     # 로그 없이 유형만
python run_demo.py --offline --out out/s1           # 키 없이 + 결과 저장
```

## 4. 데모 시나리오 (모두 가상 데이터)

| 시나리오 | 상황 | 정답 행동 |
|---|---|---|
| **S1** 계정 탈취 → 계좌 변경 사칭(메인) | M365 계정 탈취 → 숨김 규칙 → 거래처 피싱 → 거래처가 1,870만 원 송금 | 계정 침해(확인) → 송금 확인 시 **P1** → 은행 지급정지 최우선 → 24h·72h 기한 → 문서 10종(송금·개인정보 규모까지 입력한 경우. 개인정보가 판단 보류면 8종) |
| **S2** 유사 도메인 사칭 | 철자 두 글자 다른 도메인으로 계좌 변경 메일, 내부 침해 흔적 없음 | 유사 도메인(P4) — 신고 비해당, 대신 차단·고객 경고·DMARC |
| **S3** 메일 서버 root 탈취(범위 밖) | SSH 무차별 대입 → root 장악 → 로그 삭제 | **모른다고 말함** — 재부팅·삭제 금지, 전문 대응 호출, 기한만 계산 |
| **S4** 랜섬웨어 | 파일 서버·PC 암호화, 랜섬노트, 섀도 복사본 삭제, 백업 실패 | P1 → 감염 PC 분리 → 백업 보호 → **몸값 지불 금지** → KISA 118 → 문서 8종 |

첫 화면 [▶ 단계별 재생]은 데모 입력을 실제 사용자처럼 한 단계씩 보내 P3 → P2 → P1이 바뀌는 순간을 보여 줍니다. 촬영 대본: `docs/데모_시나리오_5분.md`.

**10대 사고 유형:**

- **심화(로그 판독·시나리오):** 1 BEC·계좌변경 · 2 계정 탈취 · 3 유사 도메인·스푸핑 · 4 랜섬웨어 · 5 서버 권한 탈취
- **공통 흐름(초동조치·금지행동·기한·즉답 가이드):** 6 클라우드·API 키 유출 · 7 웹·DB 유출 · 8 내부자 유출 · 9 DDoS · 10 공급망·악성코드
- 카탈로그는 `secuaid/categories.py`에 있습니다.

## 6. 설계 원칙

| 원칙 | 구현 |
|---|---|
| **계산은 규칙, 말과 근거는 모델** | 탐지·심각도·기한·할 일은 결정적 코드(같은 입력 = 같은 결과). Liner는 해석·문장·출처·재확인만. |
| **확인 / 추정 / 미확인을 섞지 않는다** | 모든 사실이 `Fact(value, level, source)`. 화면·문서에 수준을 표시하고 모르는 칸은 〔미확인〕. |
| **하지 않은 조치를 했다고 쓰지 않는다** | 신고서 '현재까지의 대응'은 체크한 일과 시각으로만 채움. |
| **민감정보를 밖으로 보내지 않는다** | 마스킹 후 전송·응답에서 복원. 서버 DB 없음(처리 중 메모리 캐시만). |
| **모르면 모른다고 한다** | 서버 자체 장악 등 범위 밖은 보존·전문 대응 호출 + 기한 계산까지만. |
| **발송은 사람이** | 초안 + 발송 전 통과표까지. 자동 제출 없음. |

## 8. API (요약)

| 경로 | 설명 |
|---|---|
| `POST /api/session` | 새 사건(선택: `category`, `scenario`) |
| `POST /api/<sid>/message` | 대화·로그 입력 → 즉시 판정(`defer:true`면 Liner 보강 작업 목록 `pending`) |
| `POST /api/<sid>/enrich` · `/law` · `/law/merge` | Liner 보강(브리핑·가이드·답변) · 법령 재확인 |
| `POST /api/<sid>/action` · `/aware` · `/ask/skip` | 할 일 체크 · 인지 시각 수정 · 질문 넘기기 |
| `POST /api/<sid>/event` · `/event/delete` | 진술 타임라인 |
| `POST /api/<sid>/evidence` · `/evidence/request` · `/evidence/search` | 증거 확보 상태 · 업체 요청 메일 · 공식 안내 찾기 |
| `POST /api/<sid>/howto` | 내장 안내 없는 할 일의 방법(Quick Answer) |
| `POST /api/<sid>/category/<id>` · `/guide` | 유형 선택 · 즉답 가이드 |
| `POST /api/<sid>/viz` | Liner 시각화 |
| `POST /api/<sid>/docs` · `/download/<id>` · `/download/zip` | 문서 초안 · DOCX/MD · ZIP |
| `GET·POST /api/<sid>/board` | 상태 토큰으로 사건 복원 |
| `GET /api/health` | 상태 · Liner 연결 · 유형·시나리오 목록 |

모든 응답은 `state` 토큰(사건 스냅샷, zlib+base64)을 함께 줍니다. 화면은 이 토큰을 매 요청 본문에 싣습니다. 서버는 메모리에 사건이 없으면 토큰으로 복원합니다. 키는 토큰에 들어가지 않습니다.

## 10. 보안·데이터

- **키:** 환경변수로만 읽습니다. `.env`는 커밋이 차단되고, 오류 메시지에 키가 섞이면 `***`로 지웁니다.
- **사건 데이터:** 서버 DB에 저장하지 않습니다. 사건은 사용자 브라우저에 보관됩니다(탭은 sessionStorage, 최근 5건은 localStorage). 사용자가 원할 때만 사건 파일(.json)로 내려받습니다.
- **공용 PC:** [저장·공유] → [이 PC에서 지우기]로 지웁니다.
- **외부 HTML:** Liner Visualization HTML은 `sandbox="allow-scripts"` 창에서 실행해 화면 데이터에 접근하지 못합니다.
- **데모 데이터:** 모두 가상입니다(RFC 5737 IP, `.example` 도메인, 가상 은행·계좌).

## 11. 한계

- **법률 자문이 아닙니다.** 신고·통지 판단은 초안이고, 최종 판단과 제출은 담당자가 합니다.
- **로그 판독 범위:** M365(로그인·감사·메시지 추적), Linux secure·방화벽, EDR·파일 서버·백업 로그를 1차 지원합니다. 그 밖의 환경은 증거 확보 도우미와 진술 타임라인으로 대신합니다.
- **보관은 브라우저 단위입니다.** 브라우저 저장소를 지우면 사라지므로, 다른 기기로 옮길 때는 사건 파일을 씁니다. 계정·서버 영속화는 범위 밖입니다.
- **Liner 응답 시간:** Search Agent(약 25초)와 Visualization(10~35초)은 시간이 걸립니다. 판정은 이미 화면에 있고, 실패해도 규칙 기준으로 계속됩니다.

## 12. 상용화 설계

지금 배포본은 **해커톤 제출용**입니다. 판정·기한·할 일·문서는 실제로 동작하지만, 계정·서버 저장·알림 없이 가볍게 만들었습니다. 같은 내용을 서비스 첫 화면 아래 **[해커톤 버전과 상용화 설계]**에서도 볼 수 있습니다.

| 항목 | 지금 (해커톤) | 상용화 |
|---|---|---|
| 서버 | Vercel 서버리스(Flask) · 미국 동부 · 요청당 60초 한도 | **국내(서울) 리전** 컨테이너 API + **작업 큐**. Liner·문서·차트는 백그라운드로 돌리고, 진행 상황은 실시간 전송 |
| 사건 저장 | 서버 DB 없음. 상태 토큰을 브라우저가 들고 다니고, 최근 5건을 localStorage에 보관 | **회사(테넌트)별 DB** · 회사별 암호화 키(KMS) · 증거 원본은 해시와 함께 객체 저장소에(보존 기간 · 삭제 잠금) |
| 사용자 | 로그인 없음 | 회사 계정 + 2단계 인증 · 역할(담당자 · 대표 · 외부 전문가 초대) · **모든 조회·수정 감사 로그** |
| Liner | 서버 환경변수의 키 1개 · 요청 중 직접 호출 | 키는 비밀 저장소에 · 회사별 사용량·한도·비용 집계 · 유형별 가이드 캐시 · 재시도와 장애 우회 |
| 로그 | 담당자가 붙여넣기·첨부 | M365 · Google Workspace 감사 로그를 **읽기 전용 OAuth 연동**으로 자동 수집 · 국내 메일 호스팅 제휴 |
| 알림 | .ics 달력 파일을 받아 직접 등록 | 마감 전 **카카오 알림톡·문자·메일**, 미처리 시 대표에게 자동 보고 |
| 규칙·법령 | 코드에 내장 · 사건마다 Liner로 재확인 | 규칙 **버전 관리**와 사건별 판단 버전 기록 · 정기 법령 재확인 배치 · 차이가 나오면 사람이 검토해 반영 |

```
웹·모바일 (담당자 · 대표 · 외부 전문가)
        │  로그인 · 2단계 인증
        ▼
API 서버 (서울 리전: 규칙 엔진 · 권한)  ──  작업 큐 (Liner · 법령 재확인 · 문서 · 알림)
        │
        ├─ 사건 DB (회사별 분리 · 암호화)      ├─ 증거 저장소 (원본 · 해시 · 보존 잠금)
        ├─ 감사 로그 (누가 언제 무엇을)        └─ Liner API (마스킹 후 전송 · 사용량 관리)
        │
        └─ 연동: M365·Google 감사 로그 · 알림톡/문자/메일 · 보험사·IT 유지보수사
```

**바뀌지 않는 원칙:**

- 판단은 규칙 엔진이, 말과 근거는 Liner가, 결정과 제출은 사람이 합니다.
- 개인정보는 가린 뒤에만 외부로 보냅니다. 상용에서는 이름·주소까지 가리도록 강화합니다.
- 신고·통지는 초안까지만 만들고, 기관 제출은 담당자가 확인한 뒤 합니다.

**단계별 계획:**

1. **시범 운영:** 회사 계정 · 서버 저장 · 마감 알림 · 감사 로그 · 국내 리전 이전 · 시범 고객 10곳
2. **자동 수집:** M365·Google Workspace 로그 연동 · 국내 메일 호스팅 제휴 · 평시 점검표·모의 훈련
3. **파트너:** 사이버보험사·IT 유지보수사(MSP) 연계 · 외부 전문가 초대 · ISMS-P 인증 준비
