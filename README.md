# 시큐에이드 (SecuAid)

> 중소·소호 기업 보안사고 초동대응 파트너 — 보안 담당자가 없는 회사의 첫 72시간을 지키는 AI
> Liner .EXE-THON 2026 제출작 (v0.13) · 배포: https://incident-note.vercel.app/

메일 계정이 뚫리거나 파일 서버가 랜섬웨어로 잠긴 날, 작은 회사의 IT 담당자는 무엇부터 해야 할지 모릅니다.
**시큐에이드** 는 **로그·메일 원본을 붙여넣으면** ① 침해 유형과 심각도를 판정하고, ② 지금 할 일과 하지 말 것을 순서대로 주며, ③ 법정 신고·통지 기한을 계산하고, ④ 통지문·신고서 초안을 만들어 주는 에이전트입니다.
로그가 없어도 **10대 사고 유형 중 하나를 고르는 것만으로** 공통 초동조치·기한·유형별 즉답 가이드가 바로 작동합니다.

**계산은 규칙 엔진이, 해석과 문장은 Liner가, 최종 판단과 발송은 사람이 합니다.**

- **v0.13 (현재) — [Liner 연동]을 누르면 Liner API 활용 안내**
  - 오른쪽 위 상태 알약(모바일 ● ⓘ)을 누르면 **Liner API 활용** 창: 처리 흐름(입력 → 개인정보 가림 → 규칙 엔진 즉시 → Liner 뒤따라), 원칙(판단은 규칙 엔진·말과 근거는 Liner·결정은 사람), **API 5종 카드**(Mark · Quick Answer · Search Agent · Search · Visualization — 엔드포인트·인증·화면 위치·하는 일·호출 시점·[화면에서 보기]), 안전장치(마스킹·API별 시간 제한·'추정'으로만 반영·격리 창).
- **v0.12 — 데모가 아니라 실제로 쓰는 날을 위해: 이어 하기 · 어떻게 하나요? · 저장·공유**
  - **진행 중인 사건 이어 하기**: 사건은 이 브라우저(localStorage)에 최근 5건 자동 보관 — 창을 닫거나 다음 날 열어도 첫 화면 '진행 중인 사건'에서 체크·타임라인·증거 표시 그대로 이어 합니다. 함께 쓰는 PC를 위해 [지우기]·[이 PC에서 지우기]. 서버 DB에는 여전히 저장하지 않습니다.
  - **사건 파일(.json) 저장·열기**: 다른 PC·다른 담당자에게 넘기거나 보관용. 파일을 열면 새 세션으로 그 화면이 그대로 복원됩니다(상태 토큰 기반, 서버 인스턴스와 무관).
  - **어떻게 하나요?**: 할 일마다 [어떻게?](맨 위 '지금 가장 먼저'에는 [어떻게 하나요?]) — 어디에 연락·준비할 것·순서·**전화할 때 할 말(복사)**·주의. 은행 지급정지, 거래처 확인 전화, 경찰·KISA 신고, 계정 정지, 감염 PC 분리, 백업 분리, 몸값, 메일 원본 저장, 흔적 보존, 업체 지원 요청 등 17종 내장(`data/action_howto.json`). 내장 안내가 없는 일은 **Liner Quick Answer**가 사건 맥락으로 '처음 하는 사람용' 순서를 출처와 함께 찾습니다(`POST /api/<sid>/howto`).
  - **저장·공유**(상단 버튼): 사장님·팀에 보낼 **카카오톡용 요약**(심각도·인지 시각·한 일·다음 할 일 3개·신고 마감) 복사/휴대폰 공유, **신고 마감 달력 파일(.ics, 2시간·30분 전 알림)**, 사건 파일 저장.
  - 로고 = 첫 화면(모바일에서 새 사건 시작), 체크 저장 중 창을 닫으려 하면 한 번 확인.

## 1. 30초 실행

```bash
# 1) 의존성 (Flask 1개 + 선택: python-docx)
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 2) Liner API 키 설정 (https://platform.liner.com/ko/keys 에서 발급)
cp .env.example .env
#   .env 파일을 열어 LINER_API_KEY=sk_live_... 값을 채웁니다. (코드에는 절대 넣지 않습니다)

# 3) 실행
python app.py
#   → http://127.0.0.1:8000
```

키 없이도 동작합니다. `.env`에 키가 없으면 **규칙 기반 모드**로 자동 전환되어 판정·기한·문서는 그대로 나오고, Liner가 맡는 해석·문장·근거 인용만 꺼집니다.

CLI로 바로 확인하려면:

```bash
python run_demo.py                                  # S1 메인 시나리오
python run_demo.py --scenario s2_lookalike_domain   # 유사 도메인 사칭
python run_demo.py --scenario s3_selfhosted_root_out_of_scope
python run_demo.py --scenario s4_ransomware         # 랜섬웨어(v0.5)
python run_demo.py --category CAT07_WEB_DB_LEAK     # 로그 없이 10대 유형만 골라 공통 흐름
python run_demo.py --offline --out out/s1           # 키 없이 + 결과 저장
```

화면 사용법 (v0.7 — 탭 워크스페이스):
- **첫 화면 4대 강점 스트립** — ① 로그·`.eml` 자동 판별 ② 24h·72h 법정 기한 + Liner 근거 ③ 지금 할 일·금기 가드레일 ④ 신고서·통지문 DOCX 원클릭. 처음 접속한 사람과 심사위원이 3초 안에 서비스 가치를 파악합니다(좁은 화면은 한 줄 가로 스크롤).
- **좌 `대화 & 증거 입력`** — 빠른 상황 예시 칩 3개, **`.csv`/`.eml` 파일 첨부**(브라우저에서 읽고 UTF-8 실패 시 EUC-KR로 재시도), 채팅, 입력창(Ctrl/⌘+Enter 전송).
- **우 `대응 보드` 3탭** — ① **초동대응·법정기한**(지금 할 일 + 신고·통지 기한) ② **판정·타임라인·Liner 차트**(판정·하지 말 것·즉답 가이드·차트·확인/추정/미확인·타임라인·근거) ③ **문서 초안 MD/DOCX/ZIP**. 탭마다 항목 수 배지가 붙습니다.
- **모바일(≤900px)** — 상단 탭 `대화 / 할 일·기한 / 판정·차트 / 문서` 로 **한 번에 한 화면씩** 전환합니다. 같은 기능을 그대로 쓰되 세로 스크롤이 길어지지 않습니다.
- **사고 유형 선택기(10개 칩)** — 고르면 그 유형의 공통 초동조치·하지 말 것·법정 기한과 **유형별 즉답 가이드**(Liner Quick Answer, 키가 없으면 규칙 기반 안내)가 즉시 나옵니다. 핵심 4종에는 `심화` 표시가 있고, 탐지된 로그와 맞는 유형은 주황 테두리로 추천됩니다.
- **[▶ 단계별 재생]** — 시나리오의 데모 입력(전화 진술 → 메일 원본 → 로그 3종 → 송금 사실 → 개인정보 규모)을 실제 사용자처럼 대화창에 하나씩 보내며, 심각도가 **P3 → P2 → P1** 으로 바뀌는 순간을 상단 배지·대화에 표시합니다. 재생 중 다시 누르면 멈추고 이어서 직접 입력할 수 있습니다.
- **[한 번에 실행]** — 같은 입력을 서버에서 한 번에 처리하고 결과만 보여 줍니다.
- **[문서 초안 생성]** → 통지문·신고서 8~10종(유형에 따라 다름). 문서마다 미리보기·MD·DOCX, **전체 ZIP** 은 사건 리포트 + 전 문서(MD·DOCX)를 한 번에 내려받습니다. 내려받는 파일 이름은 `시큐에이드_<문서명>_<id>.docx` 처럼 한글로 나옵니다.
- **[차트로 보기]** — Liner Visualization API가 이 사건의 0~72시간 대응을 HTML 차트로 그려 모달 iframe에 띄웁니다. 키가 없거나 실패하면 깨지지 않고 **요약 폴백 카드**(구간별 할 일 수 + 다음 기한)로 대체합니다.
- 가로 넘침(`overflow-x`)은 모든 화면 폭에서 제거했습니다.

## 5. 설계 원칙 (왜 LLM에게 다 맡기지 않았나)

| 원칙 | 구현 |
|---|---|
| **계산은 규칙, 판단·문장은 모델** | 심각도·기한·타임라인·탐지는 `severity/deadline/detect`의 결정적 코드. 같은 입력이면 같은 출력. LLM은 해석과 문장만. |
| **확인 / 추정 / 미확인을 섞지 않는다** | 모든 사실이 `Fact(value, level, source)` 이고, 문서·화면·응답이 수준을 항상 표시. 모르는 칸은 `미확인`으로 남기고 지어내지 않음. |
| **"결과 없음"을 "피해 없음"으로 쓰지 않는다** | 로그 종류가 빠지면 `notes`에 한계를 기록하고, 신고 판단은 `판단 보류`로 남김. |
| **민감정보를 밖으로 보내지 않는다** | `mask.py`가 주민번호·전화·계좌·카드·이메일(도메인 유지)을 토큰으로 바꾼 뒤 Liner로 전송하고, 응답에서 복원. |
| **발송은 사람이** | 문서는 초안 + 발송 전 통과표까지만. 링크 삽입 금지, "피해 없음" 단정 금지. |
| **모르면 모른다고 한다** | 서버 자체 장악은 플레이북 범위 밖 → 아는 척하지 않고 전문 대응 호출 + 기한 계산까지만. |

## 8. Vercel 배포 (서버리스)

```bash
# 1) Vercel CLI (또는 대시보드에서 저장소 연결)
npm i -g vercel && vercel link

# 2) 환경변수 (대시보드 → Settings → Environment Variables 와 동일)
vercel env add LINER_API_KEY production      # sk_live_... (필수)
vercel env add LINER_MODEL production        # liner-mark-1.3 (선택)
vercel env add LINER_TIMEOUT production      # 120 (선택)
vercel env add LINER_OFFLINE production      # 0 (키 없이 시연하려면 1)

# 3) 배포
vercel --prod
```

| 파일 | 역할 |
|---|---|
| `api/index.py` | `app`(Flask WSGI)을 노출하는 Vercel Python 진입점. 프로젝트 루트를 `sys.path`에 넣고 `app.py`를 import |
| `vercel.json` | `functions.includeFiles`로 `data/ templates/ static/ incident_note/ app.py`를 함수 번들에 포함, `maxDuration: 60`, 모든 경로를 `/api/index`로 rewrite |
| `requirements.txt` | Vercel이 그대로 설치(flask, python-docx) |
| `.vercelignore` | `.env`·`out/`·`tests/` 업로드 제외 |

**왜 Stateless인가:** 서버리스는 인스턴스가 바뀌거나 콜드 스타트하면 메모리 세션이 사라집니다. 그래서 모든 응답이 `state` 토큰(사건 상태 스냅샷, 약 20~40KB)을 함께 주고, 화면(`static/app.js`)이 이를 `sessionStorage`에 보관해 매 요청에 싣습니다. 서버는 메모리에 있으면 그대로 쓰고, 없으면 토큰으로 `Agent`를 복원합니다.

- 기존 경로(`POST /api/session`, `POST /api/<sid>/message`)와 404 동작은 그대로라 이전 테스트·클라이언트가 깨지지 않습니다. 토큰이 없으면 예전처럼 404입니다.
- 키는 토큰에 들어가지 않습니다(스냅샷은 사건 상태만 직렬화, 테스트로 고정).
- 파일 다운로드(GET)는 `?state=` 쿼리로 복원합니다.

> `includeFiles`를 지원하지 않는 구형 Vercel 프로젝트라면 `builds` 대신 대시보드의 **Root Directory**를 저장소 루트로 두고 배포하세요. 그래도 안 되면 `vercel.json`의 `functions` 블록을 지우고(제로 컨피그) `api/index.py`만으로 배포해도 동작합니다.

## 9. 한계

- 법률 자문이 아닙니다. 신고·통지 판단은 규칙 + Liner 근거로 **초안**을 만들고, 최종 판단은 담당자/전문가가 합니다. 자동 제출은 하지 않습니다.
- M365(Entra·통합 감사·메시지 추적)와 Linux secure/방화벽 로그를 1차 지원합니다. Google Workspace·국내 호스팅 로그는 같은 정규화(`ingest.py`)에 파서를 추가하면 됩니다.
- 사건 상태는 서버 메모리 **캐시** + 브라우저가 들고 다니는 `state` 토큰(zlib+base64 스냅샷)입니다. 서버가 바뀌어도 이어지지만, 브라우저 저장소를 지우거나 새 기기에서 열면 사건이 보이지 않습니다(계정·DB 영속화는 범위 밖).
- Visualization 아티팩트는 Liner가 만든 HTML을 `iframe sandbox="allow-scripts"`로 렌더합니다(부모 페이지 접근 불가). Liner 아티팩트는 **밝은(light) 테마**로 오는 경우가 많아 iframe 바탕을 흰색으로 둡니다(어두운 바탕이면 본문 글자색과 겹쳐 빈 화면처럼 보임 — v0.7에서 수정).
- Vercel 서버리스는 함수 실행 상한이 60초입니다. Visualization이 평균 10~35초라 보통은 한 번에 되지만, 콜드 스타트가 겹치면 `FUNCTION_INVOCATION_TIMEOUT`이 날 수 있습니다. 화면은 깨지지 않고 실패 사유를 보여 주며, **[차트로 보기]를 한 번 더 누르면** 대개 성공합니다(워밍된 인스턴스).
- 실서비스에서는 사서함 원문을 서버에 두지 않고, 마스킹된 요약만 모델로 보내는 구조를 유지해야 합니다.

6. **문서 내보내기** — 문서별 DOCX 버튼, 미리보기 복사 버튼, 전체 ZIP(`/api/<sid>/docs.zip`: 사건 리포트 + 전 문서 MD·DOCX).

## 14. v0.2 → v0.3 변경 내역

**버그·정합성**

6. 메일 원문·로그 본문에 있는 단어("문서 공유")로 사용자 의도(문서 생성)를 잘못 읽던 문제 → 원문 길이·형식 기반 분기.
